Visibility:
- **Private**: internal development and invited testing.
- **Mixed**: selected external builds and closed testing.
- **Public**: open releases.

## Release policy

Every numbered milestone must have meaningful implementation work before its version boundary. Version-boundary commits use descriptive names tied to the work that made the milestone shippable rather than generic messages such as “Release 0.5.0”.

GitHub releases are source-only. No executable artifact is attached. Generated GitHub source archives are sufficient.
